# เว็บไซต์กองช่าง เทศบาลตำบลสีแก้ว

ระบบบริหารโครงการ กองช่าง (วิศวกรรมโยธา) เทศบาลตำบลสีแก้ว อ.เมือง จ.ร้อยเอ็ด
เว็บไซต์เทศบาล: https://www.sikaew.go.th/index/

เปิดใช้งาน: https://sikaew-kongchang.vercel.app (Vercel) • https://nuttanan66447-eng.github.io/-/ (GitHub Pages)

## เก็บข้อมูลบนคลาวด์ (Supabase) และเผยแพร่บน Vercel

- **ฐานข้อมูล:** Supabase โปรเจกต์ `sikaew-kongchang` (สิงคโปร์) — โครงสร้างอยู่ใน `supabase/schema.sql`
- **เข้าสู่ระบบ:** กดไอคอนคลาวด์ที่แถบด้านบน (หรือเมนูโปรไฟล์ › เข้าสู่ระบบ) → ครั้งแรกกด **สมัครใช้งาน** แล้วยืนยันอีเมล
  ใช้ได้เฉพาะอีเมลที่อยู่ในรายชื่อเจ้าหน้าที่ (ผู้ดูแลระบบเพิ่มได้ที่ ไอคอนคลาวด์ › **จัดการเจ้าหน้าที่**)
- เข้าสู่ระบบแล้ว ข้อมูลทุกหน้า (โครงการ บันทึกหน้างาน เอกสาร ฎีกา ฯลฯ), ข้อมูลชีทที่นำเข้าจาก Google Sheet
  และไฟล์แนบ จะบันทึกขึ้นคลาวด์อัตโนมัติ ทุกเครื่องที่เข้าสู่ระบบเห็นข้อมูลชุดเดียวกัน
- ไม่ได้เข้าสู่ระบบ: ใช้งานแบบเดิม ข้อมูลอยู่ในเบราว์เซอร์เครื่องนั้น
- ออฟไลน์/เน็ตหลุด: การแก้ไขเก็บในเครื่องก่อน แล้วส่งขึ้นคลาวด์เมื่อเปิดหน้าครั้งถัดไป
- ข้อมูลชีท (ระบบเอกสาร) ซิงก์ทั้งเล่ม — ถ้าสองเครื่องแก้พร้อมกัน เครื่องที่บันทึกทีหลังจะเป็นข้อมูลล่าสุด
- ค่าเชื่อมต่ออยู่ใน `assets/config.js` (publishable key เปิดเผยได้ สิทธิ์ควบคุมด้วย RLS) เว้นว่าง `url` เพื่อปิดคลาวด์
- **Vercel:** ต่อกับ GitHub repo นี้ — push เข้า `main` แล้ว deploy อัตโนมัติ (`vercel.json` สร้าง `dist/` ด้วย `npm run build && node tools/build-dist.js`)

## พิมพ์เอกสารโครงการ — ใช้ข้อมูลจริงและเนื้อหาตามโค้ด v184

เปิดหน้าโครงการ (`progress.html?id=…`) แล้วเลื่อนไปที่ส่วน **เอกสารโครงการ** จะมีปุ่มเอกสารทุกแบบของโครงการนั้น
เช่น รายงานช่างรวม 3 เอกสาร, บันทึกข้อความรายสัปดาห์, S-Curve, รูปภาพโครงการ, ป้ายโครงการ, รายงานผลแล้วเสร็จ 100%,
แจ้งผู้รับจ้าง, ปรับลดปริมาณงาน, ผลทดสอบวัสดุ, ร่าง TOR (ว159 / e-bidding), กำหนดราคากลาง, แจ้งราคาต่ำกว่าราคากลาง 15%,
คำนวณค่า K, เชิญประชุม/รายงานการประชุมค่า K, เบิกค่าตอบแทน 3 แบบ

กดปุ่ม → กรอกฟอร์มสั้น ๆ (ข้อมูลโครงการเติมให้แล้ว แก้ไขได้) → **สร้างเอกสาร** → ดูตัวอย่าง → **พิมพ์ / บันทึกเป็น PDF** หรือ **บันทึกเป็น Word**
หน้า `documents.html` ส่วน **พิมพ์เอกสารราชการ** มีเอกสารเดียวกันให้เลือกโครงการได้ และมีเอกสารทั่วไป (ตรวจสอบอาคาร, ใบ อ.1, แบบประเมิน)

เบื้องหลังใช้โค้ดระบบ v184 เดิม (`system.html`, ซ่อนจากเมนู) เป็นตัวสร้างเอกสาร โค้ดฝั่งเซิร์ฟเวอร์ (`Code.gs`, `Config.gs`)
รันในเบราว์เซอร์ผ่าน Web Worker และจำลอง Google Sheets ไว้ในเครื่อง จึงไม่ต้องเปิด Apps Script

เว็บใช้ข้อมูลจริงเท่านั้น (ไม่มีโครงการตัวอย่าง): ลงทะเบียนโครงการด้วยฟอร์มโครงการ หรือนำเข้าโครงการทั้งหมดจาก Google Sheet
รายชื่อผู้ควบคุมงาน บุคลากร (คณะกรรมการ) และหมู่บ้าน มาจากระบบ v184 (`assets/personnel.js`)
ช่องวันที่ทุกช่องใช้ปฏิทินภาษาไทย (`assets/thai-date.js`) แสดงแบบ "15 มิถุนายน 2569"

### นำข้อมูลจริงจาก Google Sheet เข้าเว็บ (2 ขั้นตอน)

1. กด **นำเข้าข้อมูลจริง** ที่แถบด้านบนของหน้าเว็บ → **ดาวน์โหลดไฟล์ Excel จาก Google Sheet**
   (ต้องเข้าสู่ระบบ Google ด้วยบัญชีที่เปิดชีทของกองช่างได้)
2. กด **นำเข้าไฟล์ Excel (.xlsx)** แล้วเลือกไฟล์ที่ดาวน์โหลดมา — ข้อมูลทุกชีทจะเข้าระบบทันที

เมื่อนำเข้าแล้ว หน้าเว็บหลักทั้ง 5 หน้า (ภาพรวม ทะเบียนโครงการ ฯลฯ) จะแสดงโครงการจริงชุดเดียวกันอัตโนมัติ

### ส่งข้อมูลที่แก้ไขกลับไป Google Sheet

แผงข้อมูล (ปุ่ม **นำเข้าข้อมูลจริง**) → **ส่งออกข้อมูลเป็น Excel** → ใน Google Sheet เลือก ไฟล์ › นำเข้า › อัปโหลด › **แทนที่สเปรดชีต**

### ข้อควรทราบ

- ไม่ได้เข้าสู่ระบบคลาวด์: ข้อมูลอยู่ในเบราว์เซอร์ของเครื่องที่นำเข้า (IndexedDB) แต่ละเครื่องต้องนำเข้าเอง — เข้าสู่ระบบคลาวด์เพื่อใช้ร่วมกันทุกเครื่อง (ไม่ได้ซิงก์กับ Google Sheet อัตโนมัติ)
- ต้องเปิดผ่านเว็บไซต์ (GitHub Pages หรือ `npm start`) — เปิดไฟล์จากเครื่องโดยตรงไม่ได้
- เอกสารดาวน์โหลดในระบบเดิมเป็นลิงก์ Google Drive จะเปิดได้เมื่อไฟล์นั้นแชร์ให้บัญชีที่ใช้อยู่
- ปุ่มดึงดัชนีค่า K อัตโนมัติจากเว็บ สนค. อาจถูกเว็บปลายทางปฏิเสธ ให้กดเปิดเว็บดัชนีแล้วกรอกค่าเอง (ระบบเดิมรองรับอยู่แล้ว)
- ผู้ใช้เริ่มต้นตามโค้ดเดิม (เช่น admin / 1234) ใช้ได้จนกว่าจะนำเข้าชีทผู้ใช้งานจริง

### อัปเดตเป็นโค้ด v184 รุ่นใหม่

วางไฟล์ที่ส่งออกจาก Apps Script ทับใน `system/src/` (Index.html, Style.html, Dashboard.html, Client.html, Config.gs, Code.gs) แล้วรัน

```bash
python3 tools/build_system.py   # สร้าง system.html และ system/server/*.js ใหม่
```

## การเก็บข้อมูล (สำคัญ)

- ถ้ายังไม่ได้นำเข้าข้อมูลจริง หน้าเว็บหลักจะแสดง **ข้อมูลตัวอย่าง** พร้อมแถบแจ้งด้านบน
- ข้อมูลบันทึกใน **เบราว์เซอร์ของเครื่องที่ใช้งาน** (localStorage + IndexedDB สำหรับไฟล์แนบ) — ไม่มีเซิร์ฟเวอร์กลาง
- แต่ละเครื่อง/เบราว์เซอร์มีข้อมูลแยกกัน ล้างประวัติเบราว์เซอร์แล้วข้อมูลหาย
- เมนูรูปผู้ใช้ (มุมขวาบน) มี **สำรองข้อมูล / นำเข้าข้อมูล / คืนค่าข้อมูลตัวอย่าง** — ควรสำรองเป็นประจำ
- ข้อมูลตั้งต้นเป็นข้อมูลตัวอย่าง แก้ไขได้ใน `assets/data.js` หรือแก้ผ่านหน้าเว็บ
- หากต้องการให้หลายคนใช้ข้อมูลชุดเดียวกัน ต้องเพิ่มระบบหลังบ้าน (เช่น Google Sheets, Firebase, Supabase)

## โครงสร้างไฟล์

```
*.html                 หน้าเว็บ 5 หน้า
assets/data.js         ข้อมูลตั้งต้น + ที่เก็บข้อมูล
assets/ui.js           modal, ฟอร์ม, แจ้งเตือน, ดาวน์โหลด, เมนูส่วนหัว
assets/docs.js         แม่แบบเอกสารราชการสำหรับพิมพ์
assets/flows.js        ขั้นตอนงานที่ใช้ร่วมกัน (ตรวจรับ, ว.119, เอกสาร)
assets/pages/*.js      สคริปต์เฉพาะแต่ละหน้า
assets/realdata.js     แปลงข้อมูลโครงการจริงจากระบบงานเอกสารมาแสดงบนหน้าเว็บหลัก
assets/doc-engine.js   ฟอร์ม/พรีวิว/พิมพ์เอกสารโครงการ (สั่งงานโค้ด v184 ใน iframe ที่ซ่อนอยู่)
assets/gas/            ตัวจำลอง Apps Script (gas-emulator, gas-worker, gas-bridge) + แผงนำเข้า/ส่งออกข้อมูล
assets/vendor/         Leaflet (แผนที่), Chart.js (กราฟ), SheetJS (อ่าน/เขียน Excel)
system.html            ตัวสร้างเอกสาร v184 ที่ซ่อนจากเมนู (สร้างจาก system/src ด้วย tools/build_system.py)
system/src/            ไฟล์ต้นฉบับจาก Apps Script (ไม่แก้ไข)
system/server/         Config.gs + Code.gs สำหรับรันใน Web Worker
design/                งานออกแบบต้นฉบับจาก Google Stitch
```

## แก้ไขหน้าตา

```bash
npm install
npm run build   # สร้าง assets/styles.css ใหม่ (ต้องรันทุกครั้งที่เพิ่มคลาส Tailwind ใหม่)
npm start       # เปิดดูที่ http://localhost:3000
```
